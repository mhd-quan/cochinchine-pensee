# v0.6.4 — Loading and search snippets

## Changes

| Area | Before | After |
| --- | --- | --- |
| Responsive art | WebP, six widths; portrait sizes described the surrounding frame | AVIF with WebP fallback, nine widths; sizes describe the painted portrait or book jacket |
| Homepage LCP art, 800px | 87.1 KiB WebP | 49.1 KiB AVIF, about 44% smaller at the same width |
| Fonts in the supplied 15-file dependency list | 341.1 KiB of font file bytes | 277.0 KiB, about 19% smaller; same families, weights and shaping features |
| Shared stylesheet | 51.4 KiB uncompressed, including article prose | 39.7 KiB; article prose loads with article pages |
| Homepage blocking stylesheets | Two external requests | One; the small route stylesheet is included in HTML |
| Cache | Hashed Astro assets revalidated on every visit | One-year immutable cache for hashed Astro assets; HTML still revalidates |
| Navigation and book shelf | Viewport prefetch; immediate shelf measurement | Hover/focus/touch prefetch; shelf measurements near the viewport, batched per animation frame |
| Search descriptions | Generic archive copy; short article subtitles; technical footer colophon | Page-specific descriptions, excerpt/dek-first article summaries, shared navigation/footer excluded from snippets; colophon removed |
| Newsletter follow-up | Substack iframe in the footer and Subscribe page | Site-styled copy and a direct Substack subscription link on desktop and mobile; embed component removed |

The size comparisons above use generated file bytes, not estimated PageSpeed
savings. Font totals refer to the same 15 files, not every generated font or a
guaranteed request count for every device. Small route CSS increases HTML size
in exchange for removing a blocking round trip. AVIF encoding adds work to a
first build; subsequent builds reuse generated assets. Browser image processing
and additional tracking services are not introduced.

GA4 and the Cloudflare beacon remain unchanged. The beacon's legacy-code and
cache-lifetime warnings are controlled by Cloudflare. The Astro ClientRouter
and reader theme lifecycle are retained; the shelf change does not claim to
eliminate every router or third-party forced layout.

## Verification

- Production static build: 75 pages.
- Astro check: zero errors and warnings; 44 existing hints.
- 13 automated checks, including every advertised AVIF/WebP candidate's deployed
  file, dimensions, format and aspect ratio; LCP priority/fallback; reader
  preferences, Back/Forward and canonical/indexing regressions.
- All supported publication characters retained across 12 font/style combinations
  and 52 generated subsets, checked against the original font character maps.
- Browser review at 1280px and 390px: existing typography and image treatment,
  responsive image selection, shelf controls, article navigation and Night →
  Paper → Night Back/Forward behavior. No horizontal page overflow at 390px.
- Original uncommitted newsletter work in the separate `site` checkout is preserved.

Newsletter follow-up: rebuilt all 75 pages and reran Astro check and all 13 tests.
Every generated page retains the subscription link and contains no Substack
iframe. Browser review covered the desktop and 390px mobile footer, the mobile
Subscribe page, and navigation to `https://archyatt.substack.com/subscribe`.
No mobile horizontal overflow or browser console errors were observed.
This follow-up retains package version 0.6.4; the existing published tag is unchanged.

The variation is why this release does not promise a Lighthouse score. After
production deployment, repeat the same initial-load mobile and desktop test
three times and compare median metrics alongside transferred resources. Keep
analytics enabled in both measurements. Check the live cache headers as well.

Google may use a query-specific snippet instead of the meta description.
After deployment, request recrawling in Search Console; existing results can
retain older text until Google revisits the page. See Google's
[snippet documentation](https://developers.google.com/search/docs/appearance/snippet).
