# v0.9.2 — Browser API compatibility audit

This maintenance release adds browser deprecation checks; it does not claim to
fix the three Cloudflare warnings reported on production on September 14, 2026.
No application API migration was applicable to those warnings.

## Findings

All three warnings in the supplied report point to
`/cdn-cgi/challenge-platform/scripts/jsd/main.js`, line 0, column 1622.
Cloudflare serves this JavaScript Detections script at the edge, even though its
URL uses the publication's hostname. It is not an Astro asset or an npm package
maintained in this repository.

| Warning | Meaning and action |
| --- | --- |
| `SharedStorage` | Chrome lists Shared Storage for deprecation/removal. The publication does not use this advertising-related API; no replacement is needed in application code. |
| `Fledge` | FLEDGE is the former name of Protected Audience, also listed for deprecation/removal. Renaming an API does not resolve this warning. |
| `StorageType.persistent` | Chromium recommends the standard `navigator.storage` interface for old persistent quota usage. The appropriate method depends on the operation; it is not a mechanical replacement with `persist()`. No such application call was found. |

Source and built HTML/JavaScript were searched for the reported APIs and related
entry points. No matches were found. The source location establishes ownership;
it does not establish whether Cloudflare calls an API or merely probes its
availability while collecting browser signals.

A fresh production check with Chrome 152.0.7977.83 reproduced `SharedStorage`,
`PersistentQuotaType` and `Fledge`, all from the same Cloudflare script (its
current column was 3327). The homepage returned HTTP 200. Script offsets can
change independently of a website deployment.

## Changes

- Advance package and lockfile release metadata to `0.9.2`.
- Extend the existing local browser quality suite to subscribe to Chrome's
  `Audits.issueAdded` events before navigation. Fail on `DeprecationIssue`,
  retaining the type and source location for diagnosis, across the existing
  route/viewport matrix and search interactions.
- Keep the check local: production-injected Cloudflare scripts are not part of
  this suite. Passing it is not a claim that production Lighthouse has no warnings.

There are no runtime code, dependency, cache, analytics or security-setting
changes. The added check ships no JavaScript to readers. Cloudflare must update
its managed script to address its warnings. Do not copy or patch that script,
override browser globals, or suppress warnings with page code. Disabling bot
protection is a separate security decision, not an API upgrade.

## Verification

- `npm run verify` passed: static build, Astro check, lint and all 54 tests.
  The existing lint warnings are unchanged; no dependency was upgraded.
- Existing browser smoke checks and all 72 route/viewport combinations passed,
  including search failure/retry, navigation and JavaScript-disabled fallbacks.
  No browser API deprecations were observed in the local quality suite on
  Chrome 152.0.7977.83. This covers exercised paths, not every possible browser
  or future Chrome release.
- A temporary negative-control copy of the test accessed
  `navigator.webkitPersistentStorage`. The new assertion failed with
  `PersistentQuotaType`, confirming that it catches a real browser deprecation.
  That deliberate deprecated access is not included in the repository.
