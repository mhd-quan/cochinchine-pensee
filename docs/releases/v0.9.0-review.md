# v0.9.0 release review — 10 September 2026

The review starts from `72511f6`, the consolidated v0.9.0 proposal in PR #31.
The replacement review branch targets `main` directly and retains all that
history. This review does not establish which model authored earlier work.

## Findings and corrections

| Before | After |
| --- | --- |
| GA4 stopped retaining early navigation as soon as the script request began. Two navigations during a slow download produced no queued page views. | Continue retaining each distinct Astro visit until the script has loaded, then hand tracking back to the existing Enhanced Measurement behavior. A regression test fails on the previous implementation and passes with the fix. |
| The benchmark reported the lifetime sum of layout shifts as CLS. | Compute the largest session window with gaps below one second and duration below five seconds; retain the raw shifts and actual LCP element for inspection. Tests cover independent sessions, recent input and the five-second boundary. |
| Benchmark runs could report timings despite page exceptions or HTTP failures. | Reject runs with page errors, local HTTP errors or no observed LCP; validate the run count, verify the build exists and close browser/server resources on failure. |
| The consolidated checkout retained dependencies and generated output from an older release. | Reinstall the lockfile, rebuild, and provide `npm run verify` to run build, Astro check, lint and tests in order. Ignored files are never evidence that the current source passed. |
| Repository lint returned 43 errors and 14 warnings. | Apply the repository's formatter/import ordering rules: zero errors; the same 14 existing warnings remain visible. No lint rules were disabled. |
| The browser smoke checks were temporary local scripts. | Commit `scripts/browser-smoke.mjs` covering mobile/desktop, carousel keyboard/picker controls, Astro article/back navigation, and discovery HTTP failure/retry/Vietnam date rollover. |

The GA4 fix preserves the current automatic history tracking configuration. It
does not introduce unconditional manual page views: those can duplicate Enhanced
Measurement events even with `send_page_view: false`, as explained in
[Google's page-view documentation](https://developers.google.com/analytics/devguides/collection/ga4/views).
The CLS computation follows the [session-window definition](https://web.dev/articles/cls).

## Measurements and acceptance limits

The supplied WebPageTest JSON contains three mobile first views. Median LCP is
1,372 ms; median TTFB is 635 ms; median TBT is 164 ms. All three LCP nodes are H2
text. The second run's HTML is 399,477 uncompressed bytes and 48,829 compressed
bytes, using zstd. Thus the page was already compressed; raw HTML size is not
the transferred size. Its DOM delta is 3.04 KB / 0.77%, while the first run has a
larger 81.51 KB / 20.73% delta. A single screenshot does not describe every run.

The rebuilt review homepage is 196,678 raw bytes. Five corrected local mobile
runs yield LCP values of 992, 588, 572, 576 and 584 ms (median 584 ms), each on
`h2.hero__title`. CLS ranges from zero to approximately 0.0001915. The harness
uses Chrome, 390 × 663 at DPR 3, 4× CPU slowdown, 170 ms latency, 9 Mbps download,
disabled browser cache and a two-second observation period after load.

These local runs block external requests. They cannot be compared directly with
the production WebPageTest numbers to claim a 50% speedup. The original local
comparison reported approximately 26% LCP improvement; production acceptance
still requires matched before/after runs with the same location, device,
connection, browser and third-party behavior. A 50% reduction against the
supplied median would require production median LCP at or below 686 ms.

The three cache warnings belong to the Cloudflare challenge, Cloudflare beacon
and Google-hosted gtag script. First-party `_headers` cannot set the cache policy
of those vendor-managed responses. The shown redirect is also inside the
Cloudflare challenge path. This review does not change Cloudflare security or
analytics account settings. Partytown remains excluded because the previous
experiment did not establish reliable analytics; it is not counted as delivered.
